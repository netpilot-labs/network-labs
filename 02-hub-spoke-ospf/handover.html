04Routing

  • Protocol: OSPF process 1, single area 0 on every router. No redistribution, no default route, no static routes.
  • Interface assignment: by network … area 0 statements under router ospf 1. Do not use interface-level ip ospf 1 area N. On IOS it overrides the network statement, which is exactly what broke Branch B today.
  • WAN links: ip ospf network point-to-point on both ends (no DR election; adjacency forms in seconds).
  • LANs and loopbacks: passive-interface. They are advertised, but OSPF hellos are not sent to users.
  • Expected tables: HQ-R1 has 2 FULL neighbors and 4 OSPF routes. Each branch has 1 FULL neighbor (10.255.0.1) and 5 OSPF routes. Branch-to-branch traffic goes through HQ-R1 (cost 30 for the far branch LAN).
  • No redundancy: a branch WAN link or HQ-R1 failure isolates that branch. This is by design (one link per branch) and has not been failure-tested.

05What failed today

Symptom: users at Branch B could reach their own gateway but nothing at the head office.

Cause: an interface-level ip ospf 1 area 1 appeared on BRB-R1 Ethernet0/1. That put the WAN link in area 1 on BRB-R1 while HQ-R1 runs it in area 0. The routers rejected each other's hellos, the adjacency dropped, and both sides withdrew the routes.

Impact: Branch B ↔ head office unreachable; the adjacency was down from 16:21:58 to 16:25:04 UTC (BRB-H1 → HQ-H1 0/5 at 16:24:29). Branch B ↔ Branch A uses the same link, so it would also have been cut, but that was not tested during the fault. Branch A ↔ head office was unaffected (BRA-H1 → HQ-H1 3/3 at 16:24:29).
